# ADR-0001: isolated, bounded, honest adaptive engine

Accepted before code on 2026-10-12. Place types, engine, worker, exports and UI in src/features/horizon360. Reuse geo and BatchedProvider unchanged; no solar calculation in the new module. Existing result-cache schema remains untouched.

Both modes initially use bounded adaptive rays. Detail starts with finer angular/radial sampling, refines angular discontinuities and radial peak neighborhoods. Budgets bound samples, rays, tile loads and transferred archives; worker termination is cancellation. Native block decoding, blob-backed cache and source hashes come from the existing provider. Provider bilinear sampling is explicitly not exhaustive pixel-footprint coverage. Detail results remain INCOMPLETE; a future streaming cell/sector bound engine must meet the COMPLETE gate.

Provider errors remain source-specific; failed requests never turn into zero. Stop repeated failed tiles, return partial direction data where possible. Hard budget stops are included in warnings and instrumentation. Preflight tile union is conservative, byte volume is unknown until observed, never a invented duration forecast.

Alternate exhaustive DOM disk: rejected for unrestricted radii because 0.2 m cells scale as area and existing provider downloads full source archives. Independent spatial upper bounds and a streaming service remain a release blocker.
